BaroFarm

프로젝트 신선식품 직거래 마켓 — 폐기위험 예측·동적 할인 기간 2026.05 – 06 역할 팀장 · 백엔드/인프라 배포 barofarm.duckdns.org
운영 사이트 ↗ GitHub ↗

소개

신선식품은 유통기한이 짧아 소상공인 판매자에게 폐기 손실이 큽니다. 기존 마켓은 임박 재고를 판매자가 수동으로 내려야 하고, 소비자는 그 딜을 찾기 어렵습니다. BaroFarm은 판매자에게는 폐기 위험을 미리 보여주고, 소비자에게는 마감임박 딜을 한곳에 모아주는 마켓입니다. 커머스 백엔드와 배포 인프라를 단독으로 구현하고, 클라우드 VM에 배포해 HTTPS로 사이트를 운영하고 있습니다.

운영 중인 홈 화면 (barofarm.duckdns.org)

주요 기능

  1. 마감임박 딜 전용 탭 (/deals)

    유통기한이 임박한 상품을 한곳에 모아 소비자에게 노출합니다.

  2. 폐기위험 산출 · 동적 할인

    유통기한 D-day와 재고로 폐기위험(HIGH/MED/LOW)을 평가하고, 위험도에 연동해 할인가가 바뀝니다.

  3. 판매자 폐기 대시보드

    판매자가 자기 재고의 폐기 위험을 미리 확인합니다.

  4. AI 추천가

    상품 등록 시 KAMIS 소매 시세를 근거로 판매가를 추천하고, 상품 설명은 gpt-4o-mini로 생성합니다.

  5. 회원 · 인증

    JWT 인증(탈퇴 시 토큰 즉시 무효화·블랙리스트), BCrypt 비밀번호 저장.

시스템 아키텍처

기술적 의사결정

고민

할인가를 누가 확정하나

동적 할인은 화면에 보이는 가격과 결제 시점 가격이 달라질 수 있습니다. 클라이언트가 보낸 가격을 그대로 믿으면 가격 조작에 노출됩니다.

결정

주문 시 서버가 재계산해 청구

가격 계산 로직을 서버에만 두고, 주문 시점에 서버가 폐기위험·할인율을 다시 계산해 청구합니다. 클라이언트 가격은 표시용일 뿐입니다.

고민

폐기위험을 무엇으로 산출하나

실거래 트래픽이 없는 신규 서비스라 ML 모델을 학습시킬 실데이터가 없습니다. 근거 없는 모델은 만들지 않기로 했습니다.

결정

규칙 기반 엔진 + 합성 데이터 검증

유통기한 D-day와 재고를 규칙 기반으로 평가해 HIGH/MED/LOW를 산출합니다. 행동로그는 seed 고정 파라메트릭 시뮬레이터로 합성하되, 그 위에서 계산한 지표는 전부 실측임을 문서에 명시했습니다.

고민

탈퇴한 회원의 토큰

JWT는 발급 후 만료 전까지 유효해서, 탈퇴한 회원의 토큰이 남은 유효기간 동안 살아 있는 문제가 있습니다.

결정

블랙리스트로 즉시 무효화

탈퇴 시 토큰을 블랙리스트에 올려 즉시 무효화합니다. 비밀번호는 BCrypt로 전환하고, 배포 도메인 CORS 처리까지 인증·보안 흐름을 직접 설계했습니다.

고민

AI 추천가의 근거

LLM에게 가격을 자유롭게 생성시키면 근거를 댈 수 없습니다. 판매자가 믿고 쓸 수 있어야 합니다.

결정

공공 시세를 근거로, LLM은 설명만

판매가 추천은 KAMIS 소매 시세를 근거로 하고 등락·단위 주의 문구까지 노출합니다. LLM(gpt-4o-mini)은 상품 설명 생성에만 씁니다.

트러블슈팅

배포 단계에서 만난 문제들

  1. 배포 도메인 CORS 403

    운영 도메인에서 백엔드 호출이 403으로 막혔습니다. 배포 도메인을 CORS 허용 구성에 반영해 해결했고, 이 과정을 인증·보안 흐름 설계에 포함시켰습니다.

  2. HTTPS 전환 후 혼합콘텐츠

    운영 HTTPS 전환 과정에서 혼합콘텐츠 차단이 발생했습니다. Caddy 리버스 프록시 구성을 정리해 전 구간 HTTPS로 통일했습니다.

  3. Docker MySQL 한글 깨짐

    팀 개발환경(Docker Compose)에서 MySQL 한글이 깨지는 문제를 charset 강제 설정으로 해결하고, 환경 자체를 compose로 통일해 재발을 막았습니다.
