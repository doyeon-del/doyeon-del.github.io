문제

요약·분류·선별·편집 단계 분리

경제 뉴스를 수집해 하루 한 번 이메일로 보내는 개인 프로젝트입니다. 요약·분류·선별·편집을 각각 다른 에이전트가 처리하도록 나눠, 단계별 프롬프트와 선별 기준을 따로 조정할 수 있게 했습니다.

구조

Kafka 기반 뉴스 처리 구조

Kafka 토픽 3단계로 기사와 처리 결과를 전달하고, 에이전트 4종이 요약·분류·선별·편집을 맡습니다. 이메일 발송이 성공한 뒤 오프셋을 커밋합니다(at-least-once).

테스트 구조

외부 API 호출을 대체한 파이프라인 테스트

  1. LLM 호출부를 인터페이스로 추상화 (FakeClient)

    테스트에서는 FakeClient로 LLM 응답을 대체해 API 키 없이 처리 흐름을 확인합니다. 실제 모델 호출은 별도 구현으로 분리했습니다.

  2. 발송은 성공 후 커밋

    발송이 확인된 뒤 오프셋을 커밋합니다. 발송 후 커밋 전에 실패하면 같은 메일이 다시 발송될 수 있습니다(at-least-once).

작업을 돌아보며

큐레이션과 편집을 나누니 단계마다 따로 조정할 수 있었고, 실패가 어느 단계에서 났는지 찾기도 쉬워졌습니다.

남은 과제

  • 해외 피드는 RSS 본문이 100~200자라 요약보다 번역에 가깝습니다. 원문을 가져오는 단계를 추가해야 합니다.
  • 현재 기사를 순서대로 처리하며, 측정한 가공 시간은 440초였습니다. 파티션과 컨슈머를 늘려 병렬 처리 효과를 확인할 계획입니다.
  • 실패한 기사를 따로 모으는 큐(DLQ)가 없어 실패한 기사는 건너뜁니다. 수신자 1명, 로컬 실행 상태라 배포는 하지 않았습니다.
