웹캠 기반 실시간 자세 감지·스트레칭 데스크톱 앱

프로젝트 토끼와 거북목 — SSAFY 공통 프로젝트 결과 3위 (2026.08) 팀 5인 · 팀장·FE 전담

기술 스택

Electron 43 React 19 TypeScript MediaPipe (팀) Spring Boot · WebSocket (팀) MySQL · Redis (팀) Jenkins · Docker (팀)

주요 기능

  1. 실시간 자세 감지

    거북목(구부정한 자세)·화면 근접·졸음 3가지 상태를 웹캠으로 실시간 감지하고 화면 알림으로 알려줍니다. 시스템 트레이에 상주해 창을 닫아도 백그라운드에서 감지가 이어지며, 모든 영상 분석은 사용자 PC 안에서만 이루어지고 영상은 서버로 전송되지 않습니다.

  2. 스트레칭 가이드 및 동작 판정

    설정한 작업 시간이 끝나면 스트레칭을 제안하고, 동작별 상세 가이드에 따라 올바르게 수행했는지 카메라로 판정합니다.

  3. 개인 / 팀 모드

    혼자서도, 팀 단위로도 사용할 수 있습니다. 팀 모드에서는 서로의 작업 상태를 공유하고, 팀에서 정한 시각에 팀원들과 같이 스트레칭합니다.

  4. 보상 / 상점

    세션 참여와 좋은 자세 유지로 골드를 받아 캐릭터를 꾸밉니다. 키운 캐릭터는 트레이 아이콘에도 반영되어 작업 중에도 늘 곁에 보입니다.

  5. 기록 대시보드

    개인 단위로도, 팀 단위로도 바른 자세 시간, 시간대별 그래프, 연속 기록을 확인할 수 있습니다.

알림 계층

[2] 무효화층은 재캘리브레이션이 필요한 알림, [1] 감지층은 사용자 상태에 따라 자동으로 꺼지는 알림입니다. 두 층이 동시에 발생하면 [2]층을, [2]-1과 [2]-2가 동시에 발생하면 [2]-2를 먼저 노출합니다.

기술적 차별성

온디바이스 AI

MediaPipe(Face/Pose Landmarker)를 서버가 아닌 사용자 PC의 렌더러에서 직접 실행합니다. 웹캠 영상은 어떤 형태로도 서버에 전송되지 않아, 상시 카메라 감시라는 민감한 기능을 개인정보 부담 없이 제공합니다.

개인화 캘리브레이션

목-어깨 비율의 절대값은 사람·카메라 위치마다 달라 고정 임계값으로는 판정할 수 없습니다. 시작 시 사용자의 "바른 자세"를 측정해 개인 baseline을 만들고 기준 대비 하락률(%)로 판정하며, 어깨가 화면 밖으로 나가는 상황 감지 같은 환경 점검까지 포함해 오판정을 줄였습니다. 임계값 근처에서 판정이 깜빡이지 않도록 히스테리시스·지속시간 확정 로직도 둡니다.

스트레칭 동작의 정밀 채점 엔진

관절 각도 기반으로 진행률·축 이탈·측정 불가를 분리해 채점하고, 조건별 진행률의 최솟값을 쓰는 AND 방식으로 자세 인식 정확도를 높였습니다. 판정 로직 전체가 웹캠 없이 실행 가능한 순수 함수/상태 머신으로 설계되어 유닛 테스트 22종으로 검증했습니다.

팀 세션 실시간 동기화

raw WebSocket 위에 커스텀 JSON 프로토콜을 직접 설계해 팀원 간 작업 상태 공유와 동시 스트레칭 세션을 구현했습니다. STOMP 같은 기성 메시징 규격 대신 서비스 명세에 맞춘 경량 프로토콜입니다.

시스템 아키텍처

위기 1 — AI 산출물 혼선

AI가 만든 문서가 늘수록 혼란도 늘었습니다

팀원 각자가 생성형 AI로 산출물을 만들자, 같은 기능을 서로 다르게 이해하는 일이 생겼습니다. 같은 질문에도 시점·사람·모델에 따라 AI의 답이 달라졌고, 문서끼리 서로 충돌했습니다. 합의된 기준이 없는 AI 활용은 문서가 늘어날수록 혼란을 키웁니다. 팀장으로서 먼저 한 일은 코드가 아니라 기준을 만드는 것이었습니다.

    검수를 통과한 문서만 기준 문서로 확정했습니다. AI 산출물은 초안으로만 다뤘습니다.

위기 2 — AI 모듈 지연

AI 모듈이 완성되기 전에 나머지를 먼저 완성했습니다

감지 엔진(MediaPipe)의 완성이 늦어지면 알림·세션 등 프론트 전체가 대기해야 하는 일정 위험이 있었습니다. 기다리는 대신 결과 타입을 먼저 합의하고, 나머지를 병렬로 완성하는 쪽을 택했습니다.

  1. 감지 결과 타입만 계약으로 정의

    MediaPipe 감지 엔진이 완성되기 전에, 그 출력 타입부터 팀 계약으로 고정했습니다.

  2. 시뮬레이터로 알림·세션 로직 먼저 완성

    계약된 타입을 대신 생성하는 시뮬레이터로 알림과 세션 로직을 먼저 개발했습니다.

  3. 알림 규칙은 순수 함수로 분리해 테스트 40건

    세션 18건·알림 22건의 테스트로 계약이 지켜지는지 상시 검증했습니다.

  4. AI 모듈 투입 시 알림 코드 무수정

    실제 감지 엔진이 들어왔을 때 알림 코드는 수정 없이 그대로 동작했습니다.
