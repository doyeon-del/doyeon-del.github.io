SSAFY 15기 특화 프로젝트

SSAFY 우수 프로젝트 AI 파트 · ML 모델 백엔드·프론트 연동

라떼는 馬이야:
내 성향대로 튜닝하는 AI 경마 예측 플랫폼

과정 SSAFY 15기 특화 프로젝트 (블록체인 예측 도메인) 기간 2026.08 – 2026.10 팀 6인 · AI 파트(ML 모델·봇 서버) · 백엔드·프론트 연동 결과 SSAFY 우수 프로젝트 선정 (2026.10.02)

이번 주 실제 경주 목록과 말별 예측 확률 화면입니다. 화면의 점수와 확률은 제가 만든 예측 파이프라인에서 나옵니다.

프로젝트 개요

사용자가 비율을 정하면, AI 점수로 나만의 예측이 나옵니다

한국마사회 공공데이터 445,351행으로 학습한 모델이 말마다 컨디션·스피드·주행·기수·환경·실력 6개 항목 점수를 매기고, 사용자는 어떤 항목을 더 중시할지 비율만 정합니다. 과거 경주를 다시 푸는 게임이라 정답이 이미 있으므로, 예측과 베팅은 경주 전에 블록체인에 봉인합니다. 경마와 AI를 모두 모르는 2030을 위한 교육용·비환금성 서비스입니다.

1

결과를 보지 않는 예측

모델은 그 경주 이전 기록만 입력으로 받습니다.

2

재학습 없는 개인화

비율을 바꾸면 미리 계산한 점수를 다시 섞기만 합니다.

3

화면·베팅·정산의 확률 연동

화면 확률, 봇 베팅, 배당, 정산이 같은 숫자를 씁니다.

1주차에 기존 주제(포커·룰렛)의 한계를 짚고 경마 예측으로 재제안해 채택됐습니다. 위 세 조건은 그 기획안에서 정한 설계 요건입니다.

담당 역할

담당 업무: 예측 모델과 봇 서버 개발

영역제가 한 일
ML 모델피처 42개 설계, 6축 LightGBM 랭킹 모델 학습, Plackett-Luce 결합과 검증셋 온도 보정, 7가지 승식 확률 계산까지 예측 파이프라인을 처음부터 작성했습니다.
평가 기준ML과 DL을 같은 기준으로 비교하는 공통 평가 코드와 규칙을 만들고, 게임용 경주를 학습에서 격리했습니다.
프리셋 계수배당형·역배형 프리셋의 시장 계수를 최우도로 적합하고, 프리셋 5종의 성격을 실측했습니다.
서비스 연결AI 봇 시뮬레이션과 FastAPI 봇 서버, 게임용 경주 적재, 경주 카드 확률, 정산 오류 수정, 리플레이·베팅·결과 화면을 맡았습니다.
발표·영상결선 AI 모델 장표와 대본, 무작위 기준선·신뢰구간 계산을 맡았고, 팀 서비스 소개 영상을 만들었습니다.

근거: 본인 커밋 95건(2026.08.28~09.18), 작성 문서 docs/model · docs/bot · docs/ai/ODDS.md. 딥러닝 모델, ML·DL 앙상블, 데이터 수집 자동화, 블록체인 연동, RAG 챗봇은 팀원이 맡았습니다.

ML 모델 ① 문제 정의

경마를 분류가 아닌 랭킹 문제로 정의했습니다

말마다 1착 여부를 따로 맞히면 같은 경주 안의 상대가 누구인지가 빠집니다. 그래서 경주 안 순서를 맞히는 랭킹 문제로 보고, 6개 축마다 LightGBM lambdarank 모델을 따로 학습했습니다. 축 점수는 경주 안 백분위(0~100)로 내서, 화면과 봇이 같은 값을 씁니다.

  1. 피처는 전부 '그 경주 이전' 값

    경주성적 원본에서 피처 42개를 만들었고, 모두 해당 경주 전까지의 누적값입니다. 모델이 결과를 미리 볼 길을 피처 단계에서 막았습니다.

  2. 재학습이 아니라 재결합

    축 점수를 미리 계산해 두면 사용자가 비율을 바꿀 때 가중합 한 번으로 예측이 바뀝니다. 즉시 반영하려면 결합이 선형이어야 해서, 축 6개 위에 선형 결합을 두는 구조를 택했습니다.

  3. 슬라이더는 항목이 아니라 축에

    슬라이더를 피처 42개에 붙일지 축 6개에 붙일지 정해지지 않아 화면과 서버 작업이 멈춰 있었습니다. 축 안쪽이 LightGBM이라 항목에는 가중치를 곱할 수 없다는 근거로 축 6개를 제안해 확정했습니다.

ML 모델 ② 확률 보정

점수를 실제 적중과 맞는 확률로 바꿨습니다

화면에는 "이 말이 1등 할 확률"이 나가고, 봇 베팅과 배당도 이 확률을 씁니다. 순위만 맞아서는 부족하고 확률 크기까지 맞아야 했습니다.

  • 축 결합은 Plackett-Luce로. 6개 축 점수를 Plackett-Luce 모형으로 선형 결합해 프리셋 가중치를 구했고, 단승·연승·복승 등 7가지 승식 확률은 1착 확률을 전개해 계산하는 기준 구현으로 만들었습니다.
  • 온도는 검증셋에서. 사용자 비율을 합 100으로 정규화하면 확률 분포가 평평해집니다. 이를 되돌리는 온도(T=0.0445)를 학습셋이 아닌 검증셋에서 맞췄습니다. 학습셋에서 맞추면 확률이 과신되기 때문입니다.
  • 결과. 검증 2,473경주에서 단승 예측 확률 평균 30.1%, 실제 적중 29.8%로 맞았습니다.
함께 공개한 한계
2·3착으로 갈수록 예측 확률이 낙관적이었습니다(연승 예측 71.0%, 실측 59.5%). 이 계열 모형에 알려진 편향이라 보고, 보정 전까지는 순위 비교용으로만 쓰도록 문서에 남겼습니다.

ML 모델 ③ 평가 기준

ML·DL 모델 비교와 학습 데이터 중복 수정

LightGBM은 제가, 딥러닝은 팀원이 만들었기 때문에 같은 기준이 없으면 어느 쪽이 나은지 말할 수 없었습니다. 분할·전처리·평가를 공통 코드 하나로 고정하고 규칙을 먼저 정했습니다.

  1. 테스트셋은 최종 1회만

    모델을 고르는 동안에는 검증셋만 씁니다.

  2. 오차 범위 안의 차이는 우열로 보지 않음

    표준오차(±0.85%p)의 2배보다 작은 차이는 같은 성능으로 봤습니다.

  3. 경주 단위 정렬을 매번 검사

    랭킹 모델은 경주 순서가 깨져도 에러 없이 틀린 모델이 나오므로, 데이터를 불러올 때마다 확인했습니다.

기준선 (검증 1,254경주)1착 적중
LightGBM (배당 제외 73피처)34.0%
시장 1번 인기마39.3%
무작위10.2%

성능은 절대 적중률이 아니라 무작위·시장 대비로 말하도록 기준선을 함께 세웠습니다. 이 기준으로 팀원의 딥러닝 4개 구조도 비교했고, 모두 LightGBM과 오차 범위 안이었습니다.

게임에 쓰는 경주에서 적중률이 검증셋보다 10%p 높게 나왔습니다. 게임용 경주가 학습 기간과 겹쳐, 학습한 데이터로 평가하고 있었습니다. 게임용 경주는 학습에서 빼고 점수만 매기도록 바꿨고, 검증셋 수치가 그대로인 것으로 빠진 것은 과신한 부분뿐임을 확인했습니다.

ML 모델 ④ 프리셋

프리셋별 계수 설정과 예측 결과

비율은 정확도를 올리는 장치가 아니라 안정형이냐 이변형이냐를 고르는 장치로 정의했습니다. 정확도의 최적값은 학습이 알려주기 때문입니다. 배당형·역배형 프리셋의 시장 계수는 서버의 결합식을 그대로 옮겨 최우도로 적합했습니다.

서비스 연결

봇 서버 개발과 배당·정산 연동

봇 v1 · 0 / 180 통과

봇 하나가 두 역할을 겸함

봇 9명은 배당을 무너뜨리지 않으면서 이길 만한 상대여야 했습니다. 게임용 1,166경주로 시뮬레이션했지만, 출전 두수마다 배당 상한이 달라 고정 비율로는 막지 못했고, 강도 조절 값이 말 순서를 바꾸지 못해 봇 강도도 갈리지 않았습니다.

봇 v2 · 270 / 270 통과

유동성 공급과 참가자를 나눔

하우스 유동성은 닫힌 식으로 배당 상한을 보장하고, 봇 참가자는 모델 확률에서 샘플링해 말을 고르게 했습니다. 상한 위반 0건, 봇 적중률 12~38%, 봇 수익률 −8~−20%로 기준을 모두 통과했습니다.

  • FastAPI 봇 서버. 시뮬레이션과 별도로 서비스 코드를 구현하고, 같은 방·봇이면 같은 결과가 나오는지, 요청에 경주 결과가 섞이지 않는지 등을 pytest로 확인했습니다(90/90 통과).
  • 게임용 경주 적재. 축 점수를 1,140경주 분량으로 내보내 백엔드가 기동 시 적재하게 했습니다. 표시용 지표가 섞이면 1착 적중이 4.6%p 떨어지는 것을 확인하고 축 점수만 읽게 했습니다.
  • 정산 오류 수정. 마사회 실제 확정 배당으로 정산 식을 검증해, 연승 정산이 베팅 총액의 240%까지 지급되던 오류(입상 두수 나눗셈 누락)를 찾아 고쳤습니다.
  • 배당 1.0배 문제. 배포 서버에서 직접 플레이하다 연승 배당이 1.0배로 깔리는 것을 발견했습니다. 원인은 봇의 인기마 집중(0.6)이었고, 배당 계산기가 아니라 이 값 한 줄(0.3~0.4)만 바꾸는 안을 추천했습니다.

팀 서비스 소개 영상도 만들었습니다

팀 제출용 서비스 소개 영상(91.6초)을 Remotion(React)으로 컷·자막·그래픽을 코드로 짜서 만들었습니다. 영상 변환, 얼굴 블러, 화면 캡처 같은 실행은 Claude Code가 맡았고, 장면 구성과 무엇을 넣고 뺄지는 제가 정했습니다. 실제 서비스에 없는 자동 수집 문구를 찾아 지우는 등 내용을 검수했고, 팀 제출본으로 채택됐습니다.

배운 점과 개선 방향

모델 평가 외에도 봇 베팅과 정산을 점검하면서 학습 데이터 중복과 배당 계산 오류를 발견했습니다. 예측 결과를 서비스에 붙이는 과정에서 데이터 적재, 봇 동작, 정산 식까지 함께 수정해야 했습니다.

아쉬운 점과 개선 방향

  • 봇 강도를 조절하는 값이 말 순서를 바꾸지 못한다는 건 수식 한 줄로 알 수 있었는데, 180조합을 다 돌린 뒤에야 알았습니다. 실험 전에 한 경주를 손으로 계산해 그 값이 지표를 움직일 수 있는지부터 확인하겠습니다.
  • 배당 변동 지표를 배당이 튀는 경우만 막도록 만들어서, 실제 문제였던 배당이 깎이는 경우는 보지 못했습니다. 지표는 양방향으로 만들겠습니다.
  • 2·3착 확률 보정을 끝내지 못했습니다.
